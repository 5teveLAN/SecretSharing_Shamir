附錄 3-1 · 簡報製作

這份簡報，也是 AI 寫的

  1. 01要好看：字體、留白、配色一致
  2. 02要能動：關鍵一步用動畫講清楚
  3. 03要能嵌程式：Demo 直接放進簡報裡播放
章節草稿我的筆記 → AI CodingHTML + CSS → 一章一檔chapterN.html → 合併播放index.html

chapterN.html… 拆解

一章一個檔，每頁一個 section.slide； 分配誰做哪幾章，三個人同時動工也不會撞檔。

style.css… 風格統一

顏色、字體、卡片、公式牌都收在共用的樣式檔； 分開做，看起來還是同一份簡報。

index.html… 合併

播放器自己把每一章的頁面抓進來、接上頁碼，不用手動重排整份簡報。

data-step… 動畫 （要動的話）

一頁分幾步、每步長怎樣，寫在那一頁裡面； 用 :host(.slide[data-step="N"]) 切換顯示。

~1000多行 code 0個外部套件 3個人各自開發 ＋程式直接嵌進簡報

附錄 3-2 · 檢討

AI Coding 好用，但改起來很慢

優點 · PROS

先把東西生出來，再慢慢變好

  • 快：一章不用從零開始刻版面
  • 好看：配色、字體、留白都有基本水準
  • 可以有動畫：data-step 一頁一頁講

成品約 1000 多行 code，沒有裝任何套件。

缺點 · CONS

每次修改曠日廢時

  • 10–20 分鐘才看到一次結果
  • 10w token（DeepSeek API 約 3 元／次）
  • 動畫更久：要對 step、對時間軸
  • 結果有時不正確：常常要打掉一半的 code

不只慢：改三次，有兩次得先退回上一個版本。

解法：版本控制 —— 每次改動先 commit，改壞就 git checkout 回到上一個能跑的版本；敢打掉重來，才不會卡在同一個錯誤裡。

附錄 3-3 · 下一步

下次想試：open-slide
